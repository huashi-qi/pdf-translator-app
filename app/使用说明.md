# PDF 翻译助手 —— 下载即用

一个独立软件：把英文 PDF 拖进去，自动生成中文版。
**不需要 Zotero，不需要装 Python，不需要任何配置。**

---

### 一句话结论

**除了「翻译」本身需要联网，其他功能全部离线可用。**

### 包体里的「翻译引擎」到底是什么

你看到的应该是 `runtime\pdf2zh_next.exe`。**它不是翻译引擎本身**，
只是 46 KB 的 Python 启动器（pip 生成的 `console_scripts` 包装）。

真正的核心是两个 Python 包：

| 包 | 大小 | 职责 |
| --- | --- | --- |
| **pdf2zh_next** | 0.5 MB | 翻译流程调度 + 各种在线引擎客户端 |
| **babeldoc** | 8.7 MB | PDF 版面解析与重建（**排版还原**） |

#### babeldoc 负责什么

这是最有价值的部分 —— **它让译文保持原版排版**：

- 解析原 PDF 的段落、表格、图片、公式位置
- 把文字挖掉、填入译文、重新排版
- 自动选择合适的字体、控制行距、处理中英混排

为此它自带两个离线资源：

| 资源 | 大小 | 用途 |
| --- | --- | --- |
| `doclayout_yolo_...onnx` | **71.8 MB** | 版面分析模型（识别哪里是正文/表格/图） |
| fonts（34 个） | **253.5 MB** | 排版用字体 |

> 这个 ONNX 模型是**离线跑在本地 CPU 上**的，不需要联网。

#### pdf2zh_next 负责什么

它内置 16 个翻译器，**全部是在线 API 客户端**：

```
bing / google / deepl / azure / azureopenai / openai
ollama / qwenmt / siliconflow / siliconflowfree
tencentmechinetranslation / xinference / dify
anythingllm / claudecode / clitranslator
```

**没有一个是本地翻译模型。** 包内也确认没有任何
`.gguf` / `.pt` / `.safetensors` 等大模型权重文件。

#### 所以分工是

```
┌─────────────────────────────────────────┐
│  babeldoc（离线）                        │
│  · 解析 PDF 版面（ONNX 模型本地跑）      │
│  · 挖出待翻译文本                        │
│  · 拿回译文后重新排版、填回、导出        │
└──────────────┬──────────────────────────┘
               │  文本（纯字符串）
               ▼
┌─────────────────────────────────────────┐
│  pdf2zh_next → 在线 API（需联网）        │
│  · 把文本发给 Bing / Google / ...        │
│  · 拿回中文                              │
└─────────────────────────────────────────┘
```

**排版这半截（最难的）是离线的，翻译那半截必须联网。**

#### 想完全离线怎么办

`translator_impl` 里有 **`ollama`** 和 **`xinference`** —— 这两个是
**本地推理框架的客户端**。所以：

1. 装 [Ollama](https://ollama.com)，`ollama pull qwen2.5:7b`
2. 软件里 设置 → 翻译引擎 → 自定义填 `ollama`
3. API 地址填 `http://127.0.0.1:11434`

这样**排版 + 翻译全部在本地完成**，全程零外网。

### 如果要完全离线翻译

1. 本机跑 **Ollama**（免费开源），下载一个中文能力好的模型
2. 设置 → 翻译引擎 → 自定义引擎填 `ollama`
3. API 地址填 `http://127.0.0.1:11434`

这样连本地服务，全程不碰外网。


## 给使用者

### 三步搞定

1. **解压** `PDF翻译助手.zip` 到任意位置（需要约 2 GB 空间）
2. **双击 `启动.vbs`**（推荐，无黑框闪烁）
   - 若被安全软件拦截，改用 `启动.bat`（会闪一下黑色控制台，属正常）
3. 把 PDF **拖进窗口**（或点「选择 PDF」）
4. 在弹出的确认窗口里**确认输出版本与文件名**，点「开始翻译」

翻译完成后会**自动切到「历史记录」并选中最新一条**，双击即可打开结果
（不会自动弹窗，避免打断你正在做的事）。

内置 **1046 条电子工程专业术语**（覆盖电源管理、运放/信号链、数字接口、封装可靠性、
半导体器件、射频、电机驱动、传感器、测量等），**免费引擎也生效**：

| 英文 | 内置译法 |
| --- | --- |
| Step-Down Converter | 降压转换器 |
| Low Dropout Regulator | 低压差线性稳压器 |
| Quiescent Current | 静态电流 |
| Load Regulation | 负载调整率 |
| Thermal Shutdown | 过温保护 |
| Absolute Maximum Ratings | 绝对最大额定值 |
| Common-Mode Rejection Ratio | 共模抑制比 |

实测一篇 14 页数据手册：12 个关键术语全部按术语表翻译。

### 界面说明

- **进度条**：真实百分比 + 当前阶段
- **运行日志**：翻译过程的详细输出
- **历史记录**：最近翻译的文件列表，**双击一行即可打开结果**；
  右键可选「用 WPS 打开 / 打开所在文件夹 / 复制路径」
- **设置**：引擎、并发、术语表、保存位置、输出版本、输出文件名、打开方式
  （设置项较多，窗口内**可滚动**，不会被裁掉）

### 输出文件名

默认自动命名：**原文件名 + 语言 + 版本**，例如
`SGM.no_watermark.zh-CN.mono.pdf`。

想自定义就在「设置 → 输出文件名」里填，例如填 `SGM6130数据手册`，
产出就是 `SGM6130数据手册.mono.pdf`（中文版）和
`SGM6130数据手册.dual.pdf`（双语版）——后缀自动加，两种版本不会互相覆盖。

### 打开方式（在「历史记录」页）

「历史记录」页顶部有打开方式下拉框：

| 选项 | 说明 |
| --- | --- |
| 系统默认 | 用 Windows 关联的程序打开 |
| WPS | 用 WPS 打开（自动检测安装位置） |
| 打开所在文件夹 | 直接定位到文件所在目录 |

选好后**双击历史记录任意一行**即可用该方式打开；也可用页顶的
「打开选中 / 打开文件夹」按钮，或右键菜单。另有「清空历史」按钮。

### 翻译前确认

选好 PDF 后会弹出确认窗口，里面可以：

- 选**输出版本**（中文版 / 双语对照版 / 两者都要）
- 选**输出文件名**——下拉框的选项会**随版本自动变化**：
  - 中文版 → `原文件名中文版` 或 `原文件名`
  - 双语版 → `原文件名双语对照版` 或 `原文件名`
  - 也可直接输入自定义名称

确认后才开始翻译，避免选错版本或文件名。

### 翻译速度

翻译的瓶颈是**网络往返**（实测单段约 1.7 秒），所以并发数最关键：

| 并发数 | 相对速度 |
| --- | --- |
| 4（旧默认） | 基准 |
| **10（当前默认）** | **1.7 倍** |
| 20 | 2.35 倍 |

实测 14 页数据手册：并发 4 需 83 秒，并发 10 只需 **55 秒**。

设置里可把并发调到 **1–30**，网络好就调高，遇到限流就调低。

> 同一份 PDF 翻第二遍会**秒出**——译文有本地缓存（`cache` 目录里），
> 手册中重复的句式也只翻一次。

### 已知限制：目录页会被合并

**现象**：目录、表格列表、图表列表这类"一行一条"的页面，译文会把整页
条目**合并成一个段落**，丢失点线（……）和页码。

**原因**：这是上游 babeldoc 版面分析的固有行为，不是本程序的 bug。
我实测了 8 种参数组合（`--split-short-lines`、`--short-line-split-factor`、
`--enhance-compatibility`、`--skip-clean`、`--no-remove-non-formula-lines`、
`--skip-scanned-detection` 等），**7 种渲染结果完全一致**，唯一不同的
`--enhance-compatibility` 只是跳过字体子集化（文件从 3 MB 涨到 35 MB），
版面并没有变好。

**影响范围**：仅目录/列表页；正文、表格、图表都正常。

**应对**：目录页本来就是导航用的，正文页码与原文一致，可对照阅读。
若目录很重要，建议保留原版 PDF 对照，或用「双语对照版」输出。

### 引擎连接测试

设置里点「测试连接」，会检查当前引擎/API Key 是否可用，
省得填完 Key 翻译到一半才发现不通。

### 缓存加速

同一份 PDF 翻译第二遍会**快很多**——译文有本地缓存。
每次翻译完成后，日志里会显示：
`⚡ 缓存命中 398/399 段（省去 100% 的翻译请求）`

### 失败自动降级

接口限流时会**自动把并发减半重试**（最多两次），
而不是直接失败。实测能救回大部分限流场景。

| --- | --- |
| **忽略译文缓存** | 强制重新翻译。改了术语表、或想换引擎重翻时勾选 |


## 本次新增

### 设置按类别分页

设置窗口现在分成 4 个页签：**翻译引擎 / 术语表 / 输出 / 高级**，
不用再滚一长条。多项设置改成了**下拉选择**（输出版本、完成后动作、术语领域）。

### 翻译完成后怎么打开（三选一）

设置 →「输出」页 →「完成后」：

| 选项 | 行为 |
| --- | --- |
| **每次询问我**（默认） | 翻完弹窗，让你选「系统默认打开 / WPS 打开 / 打开文件夹 / 不打开」 |
| **自动打开结果** | 翻完直接打开 |
| **不打开** | 只在历史记录里，你自己开 |

### 历史记录分组

历史页新增「分组」列和下拉筛选：

- 选中记录 → 点「分组…」→ 输入或选择分组名（如「STM32 项目」）
- 下拉框可按分组筛选，支持「全部 / 未分组 / 具体分组」
- 时间列旁有标记：**W** = 导出了 Word，**!** = 有质量告警

### 批量翻译

选 PDF 时**按住 Ctrl / Shift 多选**，就会依次排队翻译，
不用一个个来。

### 术语自动学习（免费引擎也能用）

设置 →「术语表」→「从 PDF 学习新术语…」

从 PDF 里挑出高频专业词（全大写缩写、型号、首字母大写词组），
自动排除已有术语，你填中文即可加入术语表。

**不依赖 LLM** —— 用的是「词频统计 + 术语表比对」，所以 Bing/Google 也能用。

### 术语按领域启用

设置 →「术语表」→「启用领域」：

| 领域 | 说明 |
| --- | --- |
| 全部领域（默认） | 1046 条全用 |
| 电源与转换器 / 模拟与信号链 / 数字与接口 / 半导体器件 / 封装与可靠性 / 射频与无线 | 只启用该领域 |

通用词在任何领域下都生效，只排除其它领域的专有词，避免误替换。

### 质量检查

翻完自动扫一遍译文，提示可疑点：

- **疑似漏翻**：整页几乎没有中文
- **英文残留**：中文版里还有成句英文
- **数字可能丢失**：数字个数明显变少
- **重复段落**：引擎抽风导致重复

### PDF 转 Word（不翻译，主界面）

主界面点「**PDF 转 Word**」，选 PDF 就**直接转换，不翻译**。
生成的 Word 在输出目录的 `word\` 子文件夹。

### 确认窗口的输出类型

选完 PDF 后的确认窗口，新增「**输出类型**」下拉：

| 选项 | 说明 |
| --- | --- |
| **PDF**（默认） | 只出翻译后的 PDF |
| **Word 文档** | 只出 Word |
| **PDF + Word 都要** | 两个都生成 |

> 切「输出版本」时，**输出文件名会自动跟着变**（如 SGM → SGM中文版 → SGM双语对照版）。
> 若你手动改过名字，则切换版本不再覆盖你的输入。

### 导出 Word

设置 →「高级」→「翻译后同时导出 Word 文档」。

Word 文件在输出目录的 `word\` 子文件夹里。

> **注意**：PDF 是绝对定位、Word 是流式排版，所以页数会变、复杂表格可能错位。
> Word 适合**改内容**，要**保版式**仍建议用 PDF。
> 实测一份 14 页数据手册：字符保真 100%、表格 20/20 保留、图片 19 张。

### 历史记录：删除选中

- **删除选中**：按 Ctrl 多选后删除指定记录（不必再全清）
- 弹窗里可勾选「**同时删除这些输出文件**」（默认不勾，只删记录）
- **清空全部**：删掉所有记录（仍不会动文件）
- 内置 **Word 分组**：凡产出了 Word 的记录都归到这里，下拉可选

### Word 文件放哪里

Word 统一输出到 **`输出目录\word\`**（即界面上的「Word 分组」），
和 PDF 分开存放，方便查找。

### 应用内 PDF 编辑器（主界面「打开 PDF」）

不用跳出软件，直接像阅读器一样打开 PDF 并标注：

- **翻页浏览**：上一页 / 下一页 / 跳转，100% / 140% / 200% 缩放
- **加文字**：点画布任意位置，插入文字（5 种颜色）
- **加批注**：便签图标，鼠标悬停可见内容
- **高亮**：点一下就在该处加高亮
- **涂黑**：遮盖敏感内容
- **旋转 / 删除本页**
- 改完「保存为新文件」，不会动原文件

> 渲染速度实测 0.03~0.04 秒/页，翻页很跟手。

### 历史记录删除功能三个问题

#### 1. 没有「确定」按键

**原因**：对话框里内容 `pack(expand=True)` **先**占满了空间，
按钮栏 `pack(side="bottom")` **后**才创建 —— 空间已经没了，按钮被挤出对话框外。

```python
# 错误顺序
f = tk.Frame(dlg); f.pack(fill="both", expand=True)   # 先占满
bar = tk.Frame(dlg); bar.pack(side="bottom")          # 被挤出
```

**修法**：按钮栏**先 pack**，内容区再填剩余空间。

```python
bar = tk.Frame(dlg); bar.pack(side="bottom", fill="x")  # 先占底部
f = tk.Frame(dlg); f.pack(fill="both", expand=True)      # 再填剩余
```

同时把按钮文字从「删除」改成 **「确认删除」**，更明确。

**实测**：对话框 500x420，两个按钮都在 y=373（高 420，完全可见）。

#### 2. 不能删除文件

**原因**：「同时删除这些输出文件」复选框**默认不勾选**，
用户直接点删除，只删了记录没删文件。

**修法**：**默认勾选**（有文件时）。用户点删除通常就是想连文件一起清掉；
不想删可以手动取消勾选。

**实测**：3 个测试文件 → 点确认后 **全部删除**（剩 0 个），记录也清空。

#### 3. 不支持 Ctrl+A 全选

**原因**：`ttk.Treeview` **默认没有 Ctrl+A 快捷键**，必须自己绑。

### 术语表命中：英文列空、中文错位

**根因**：`term_hits` 字典的 key 是**中文**（统计的是「替换成了哪个中文」），
而词库 `_lookup()` 的 key 是**英文**。

```python
# 错误写法（之前）
pairs = _gh._lookup()          # {英文: 中文}
gt.insert(..., values=(term, pairs.get(term, ""), cnt))
#                          ↑ term 是中文，永远查不到 → 英文列空
```

**修法**：建「中文 → 英文」的反向表。

```python
fwd = _gh._lookup()            # {英文: 中文}
rev = {cn: en for en, cn in fwd.items()}   # {中文: 英文}
```

现在显示正确：

| --- | --- | --- |
| output voltage | 输出电压 | 23 |
| step-down converter | 降压转换器 | 17 |
| soft-start | 软启动 | 18 |

> 兼容性：如果 key 本身是英文（老数据），会自动识别并互换，不会显示错位。

### 「先切换再播动画」的真正根因

这个问题修了**三次**才对，前两次都是错的，把过程记下来避免再犯：

**第 1 次**：截旧图 → 重建 → 截新图 → 播动画
❌ 重建一完成，新界面就显示出来了。

**第 2 次**：截旧图 → 独立 Toplevel 遮罩 → 重建 → 播动画
❌ 重建主窗口时 Windows 会把主窗口**激活到前面**，Toplevel 遮罩被压到后面。

**第 3 次（中间又错了一步）**：改用主窗口内的 Frame 遮罩
❌ 遮罩确实挡住重建了，但我没意识到：

| 5 | 动画窗口第 0 帧已预渲染，铺在最上层 |
| 6 | 这时才撤遮罩 —— 屏幕上无缝切到动画 |

`mode` 在启动时赋值一次，之后永不更新 —— 第二次切换会被判成「没变化」。
→ 改成每次从配置重新解析。

实测：主题 `#eef1f6 → #16181d` ✅，字号 `[8,9,10] → [11,12,13]` ✅。

### 四个「设置了没反应」的 bug —— 找到根因了

| 问题 | 根因 |
| --- | --- |
| 界面缩放无效 | `tk scaling` 只在启动时设一次，切换时不重新应用 |
| 字体大小无效 | **61 处控件的字号是写死的** `font=(FONT, 9)`，改设置根本改不到 |
| 设置里主题切换无效 | `mode` 变量启动时赋值后**永不更新**，第二次切换被判成「没变化」 |
| 翻译预设无效 | 套用预设后只做「原地换色」，控件不重建 → 下拉框还显示旧值 |

**修法**：把「原地换色」改成**真正的重建**（销毁旧界面 + 重新构建）。
为此把界面拆成了可重复调用的构建函数：
`_build_shell()` / `_register_pages()` / `_build_footer()`。

字号则改成 `_f(9)` 这种写法 —— 基准字号 + 用户偏移，
61 处写死的字号全部替换，这样调字号才真的全局生效。

实测：

| 项目 | 结果 |
| --- | --- |
| 界面缩放 | scaling 1.666 → 2.252 ✅ |
| 字体大小 | [8,9,10] → [11,12,13] ✅ |
| 主题切换 | 夜间 ↔ 白天 双向正常 ✅ |
| 切换耗时 | 约 1.3 秒，不重启进程 |
| 连续切换 | 稳定不崩 ✅ |
